# 要件と受入条件

[要求一覧](requirements.md) の要求（R-01 〜 R-16）を、実装とテストに使える要件に具体化したもの。

- 「元の要求」は、要求一覧の ID である。
- 「確かめ方」の A 〜 D は、5章のテストの種類である。
- 版と変更履歴は Git で管理する。

## 1. 用語

| 用語 | 意味 |
| --- | --- |
| プラグイン | このリポジトリで作るエージェントプラグイン。名前は `reverse`。 |
| スキル | プラグインの入口。`/reverse:make-design-docs` で呼ぶ。 |
| スクリプト | スキルが実行する Python のプログラム。同じ入力から同じ結果を出す処理を受け持つ。 |
| 担当エージェント | スキルが呼び出すサブエージェント。解析、変換、照合、執筆、検証の5つの担当がある。 |
| 出力先 | 新しい設計書と静的サイトを置くフォルダ。 |
| ユニット | ソースコードを解析するときの単位。同じフォルダのファイルを、行数の上限までまとめたもの。 |
| モジュール | 内部設計書を書く単位。ソースファイルを直接含むフォルダ1つを1モジュールとする。 |

## 2. 全体の流れ

1. 利用者が、スキルを呼び、ソースコードと PDF の場所を指示する。
2. スクリプトが、ソースコードをユニットに分け、PDF をページの画像にする。
3. 解析担当がユニットごとに解析メモを書き、変換担当が PDF を Markdown に書き起こす。
4. 照合担当が、既存の設計書の記述をソースコードと照らし合わせる。
5. 執筆担当が、モジュールごとの内部設計書と機能の要求を書き、検証担当がソースコードと照らして直す。
6. 執筆担当が、全体の内部設計書と、要求仕様書の残りの章を書く。
7. スクリプトが、食い違いの一覧、不明点の一覧、入口のページを作り、出来上がりを検査する。
8. スクリプトが、静的サイトを作り、その PC で表示する。

| ID | 要件 | 元の要求 | 確かめ方 |

| SR-07 | スクリプトは、10万行から100万行のソースコードを、ユニットとモジュールに分けられる。 | R-05 | A |

## 4. 禁止事項

- ソースコードと PDF を書き換えること。入力は読むだけとする。
- 出力先の外にファイルを書くこと。
- 推測を、事実として新しい設計書に書くこと。
- 新しい設計書の記述に、根拠の場所（ソースファイル名と関数名、PDF のページ番号）を添えること。場所を載せるのは、食い違いの一覧と不明点の一覧だけとする。
- 作業を始めた後に、利用者に質問すること。

## 5. 受入条件

要件は、次の4種類のテストで確かめる。すべてに合格したとき、完成とする。

| 種類 | 内容 | 合格の条件 |
| --- | --- | --- |
| A. スクリプトの自動テスト | pytest で、スクリプトの入出力を確かめる。 | すべてのテストが通る。 |
| B. 読み込みのテスト | Claude Code の `claude plugin validate` と、Copilot CLI の `plugin list`・`skill list` で確かめる。Copilot CLI のエージェントは、モデルに届くツールの定義で確かめる。 | プラグイン、スキル、5つの担当エージェントが、両方のツールで読み込まれる。 |
| C. 実際に動かす評価 | 公開されている組み込み向けの OSS とその仕様書の PDF を使い、Claude Code でスキルを最後まで動かす。 | 下の C-1 〜 C-5 をすべて満たす。 |
| D. Windows でのテスト | GitHub Actions の Windows で、A のテストを動かす。 | すべてのテストが通る。 |

### C の合格の条件

| ID | 条件 |
| --- | --- |
| C-1 | 利用者への質問なしで最後まで進み、スクリプトの構造の検査（SR-31）に合格する。 |
| C-2 | 新しい設計書から抜き取った記述 30 件を、作成に関わっていない独立したエージェントがソースコードと照らし合わせ、27 件以上が正しい。ソースコードにない関数名や型名が、1件もない。 |
| C-3 | 独立したエージェントが事前に見つけておいた食い違い（5件以上）のうち、8割以上が食い違いの一覧に載っている。 |
| C-4 | 変換した既存の設計書から抜き取った 10 ページを、独立したエージェントが PDF と見比べ、見出し、本文、表、図の内容に欠けと誤りがないページが 9 ページ以上ある。 |
| C-5 | 静的サイトがブラウザーで表示され、Mermaid の図が図として描かれる。 |

### テストで確かめられないこと

- GitHub Copilot CLI でスキルを最後まで動かすこと。開発の環境では Copilot CLI にログインできないため、読み込み（B）までを確かめる。
- Windows の PC でスキルを最後まで動かすこと。スクリプトの動作（D）までを確かめる。

## 6. AI の使い方

| 項目 | 内容 |
| --- | --- |
| 目的 | ソースコードと PDF の内容を読み取り、設計書の文章と図を書く。 |
| 入力 | ソースコード、PDF のページの画像と埋め込まれたテキスト、ほかの担当エージェントが書いたファイル。 |
| 出力 | 解析メモ、変換した Markdown、照合の記録、新しい設計書。 |
| 人の関わり | 利用者は、完成した設計書、食い違いの一覧、不明点の一覧を確認する。 |
| 分からないときの振る舞い | 推測を書かずに、不明点として記録する（SR-20）。 |
| 失敗したときの振る舞い | 形式の検査で不合格のものは、やり直す。直らないものは、不明点の一覧に記録して先へ進む（SR-30）。 |
| 評価 | 独立したエージェントが、抜き取りで正しさを確かめる（C-2 〜 C-4）。 |
| 再評価の条件 | スキル、担当エージェントの指示、スクリプトのいずれかを変えたときは、C の評価をやり直す。 |
