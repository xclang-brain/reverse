## 書き方

- 見出し、段落、箇条書き、表を、ページの構成のとおりに書く。見出しは、`#` の数で階層を表す。
- ページをまたぐ段落と表の行は、始まったページのファイルに最後まで書く。
- 前のページから続く表を書くときは、同じ見出しの行を付ける。
- 埋め込みテキストがあるときは、文字を埋め込みテキストのとおりに書く。読めない文字は `【判読できない】` と書く。
- 次の文字列は、ページの端に毎ページ出るヘッダー、フッター、ページ番号、行番号である。書かなくてよい。表や本文の一部として見えるときは書く。

### 表と記号

- 表は Markdown の表で書く。全部の行を `|` で始めて `|` で終え、列の数をそろえる。2行目は区切りの行（`| --- | --- |`）にする。
- 結合セルは、結合を解いて、同じ値を各セルに書く。セルの中の改行は `<br>` で書く。
- コード、識別子、`<`・`>`・`|`・`*`・`_` を含む語は、バッククォートで囲む。

例（作った名前の表の1行）：

```markdown
| 開いた状態<br>`VLV_OPENED` | `vlv_flag` の `bit_0` が `1` のとき |
```

### 図

図は、種類で書き方を決める。

| 図の種類 | 書き方 |
| --- | --- |
| 状態遷移図 | `stateDiagram-v2` |
| シーケンス図 | `sequenceDiagram` |
| ブロック図、構成図、フローチャート | `flowchart`（入れ子は `subgraph`） |
| タイミングチャート、波形、グラフ、写真、画面の絵 | 画像 |

- 表にない種類の図は、箱と線で表せるなら `flowchart`、表せないなら画像にする。
- 図の中の文字が読めない図は、画像にし、説明文に `【判読できない】` を書く。
- Mermaid で書いた図は、書いた後に画像と見比べ、箱、線、矢印の向き、ラベルが合うことを確かめる。
- 画像にする図は、`![<図の題>](figure:<x0>,<y0>,<x1>,<y1>)` の1行と、その次に `図の説明：` で始まる1段落の説明文を書く。値は、図を囲む範囲の左、上、右、下を、ページの幅と高さに対する 0〜1 の数で表す（左上が原点。例：`0.1,0.4,0.9,0.7`）。図の範囲は、迷うときは広く書く。

### Mermaid の決まり

1行目は `stateDiagram-v2`、`sequenceDiagram`、`flowchart TD`、`flowchart LR` のどれかにする。

- `flowchart`：ID は英数字にする。箱と矢印のラベルは、全部を二重引用符で囲む（`a["開く (open)"] -->|"はい"| b{"成功か"}`）。`subgraph` は `subgraph g1["名前"]` で始め、`end` だけの行で閉じる。
- `stateDiagram-v2`：状態の ID は英数字にし、日本語の名前は `state "閉じた状態 (CLOSED)" as s1` で付ける。遷移のラベルは `s1 --> s2: 開く` のように `:` の後ろに書く。
- `sequenceDiagram`：参加者は `participant c as 制御部` の形で、英数字の ID を付ける。メッセージは `c->>v: 開く` のように `:` の後ろに書く。

## 前回の不合格の理由があるとき

- 文字列の指摘は、ページの画像で確かめて直す。余分と言われた文字列が画像のとおりなら、残す。
- 前回 Mermaid の検査に不合格だった図を画像で載せるよう書かれたページは、その図を画像にする。

## してはいけないこと

- バッククォートの外に、`<br>` のほかのタグと `__` を書くこと。
- Mermaid のラベルの中に `"` と `;` を書くこと。`sequenceDiagram` のメッセージに `#` を書くこと。
- `flowchart` の ID に、`end`、`class`、`graph`、`style`、`subgraph` を使うこと。
- Mermaid で書くと決めた種類の図を、文字が読めない図と、前回の理由で画像にするよう書かれた図のほかに、画像にすること。
- 書く先のほかに、ファイルを書くこと。
