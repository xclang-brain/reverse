# 仕事 {{job_id}}：{{pdf_name}} の照合

あなたは照合担当である。この指示のファイルを読み、既存の設計書（{{pdf_name}}）の番号を振った行の全部を、ソースコードと照らして分類し、照合の記録を1つ書く。

## 読むもの

ファイルは、終わりの行まで読む。途中で切れたら、続きの行から読む。{{src_note}}

- 番号を振った行（番号は 1 から {{line_count}} まで）：{{lines_file}}
- 解析メモのフォルダ：{{memo_dir}}
- モジュールの一覧：{{modules_file}}
- ソースコードのフォルダ：{{src_dir}}

## 書く先

- 照合の記録：{{output}}

## 進め方

1. 番号を振った行を読む。
2. 行の名前や語で、解析メモを Grep で探し、ソースコードの場所の見当を付ける。
3. その場所のソースコードを読んでから、分類する。

## 分類

1 から {{line_count}} までの全部の番号を、連続した範囲ごとに、次の4つのどれかに分ける。どの番号も、ちょうど1回ずつ、どれかの範囲に入れる。表と図も、行の範囲として分ける。

| 分類 | 当てる行 |
| --- | --- |
| 一致 | ソースコードで確かめられた行。ソースコードにだけ細かい内容があるときも、一致にする。 |
| 食い違い | 同じことがらについて、既存の設計書とソースコードの内容が両立しない行。 |
| 既存設計書のみ | 確かめきれなかった行。ソースコードに見つからない機能の記述。既存の設計書の別の場所を見ないと決められない行。食い違いでない画像の図（`![…](…)` の行と、その説明文）。 |
| 対象外 | 目次、見出しだけの行のように、設計の内容を持たない行。 |

食い違いの例：既存の設計書は「弁を閉じる待ち時間は 30 秒」、ソースコードは `60` 秒を待つ。画像の行は、一致にしない。

## 記録の形式

記録は `## <範囲> <分類>` の行で始める。範囲は `<番号>` か `<開始>-<終了>` である。最初の `## ` の行より前には、何も書かない。キーの行は `- <キー>: <値>` の形で、下の例の順に、値を1行で書く。

- 一致：`- 場所:` の1行だけ。
- 食い違い：`- 場所:`、`- 名前:`、`- 既存の設計書:`、`- ソースコード:`。名前は、食い違いがある関数の名前である。関数の外の内容では、定義（型、マクロ、変数）の名前を書く。名前は、場所のファイルにある表記のまま書く。
- 既存設計書のみ：`- モジュール:` と `- 内容:`。モジュールは、モジュールの一覧の名前か `全体` である。内容は、`- 内容:` の次の行から、新しい設計書に入れる文、表、図を Markdown で書く。見出しは書かない。画像の行は、番号を振った行のとおりに書く。文は、それだけで意味が通るように、対象の名前を補って書く。
- 対象外：`## ` の行だけ。
- 場所は、`[<ソースコードのフォルダからの相対パス>:<開始行>-<終了行>]` の1個である。
- 記録の内容のうち、日本語でない文は、日本語に直して書く。名前と数値は、元の表記のまま書く。
- 内容のバッククォートには、ソースコードか既存の設計書にある名前だけを入れる。内容の Mermaid の図は、番号を振った行のとおりに書く。

例（名前は、形式を示すために作ったもの）：

```markdown
## 1-3 一致
- 場所: [pump/valve.c:52-90]

## 4 食い違い
- 場所: [pump/valve.c:95-130]
- 名前: valve_close
- 既存の設計書: 弁を閉じる待ち時間は 30 秒である。
- ソースコード: 弁を閉じる待ち時間は 60 秒である。

## 5-6 既存設計書のみ
- モジュール: pump
- 内容:

弁の制御部は、停電のときに全部の弁を閉じる。

| 弁 | 用途 |
| --- | --- |
| 1 | 給水 |

## 7 対象外
```

## 根拠の決まり

- ソースコードについての記述の根拠は、対象のソースファイルだけである。文書のファイル（md、txt、html など）は根拠にしない。
- 既存の設計書の内容の根拠は、番号を振った行だけである。

## してはいけないこと

- 書く先のほかに、ファイルを書くこと。ソースコードを書き換えること。
- 分類 `照合していない` を使うこと（スクリプトだけが使う）。
- 既存設計書のみの内容を、件数が多いことを理由に省くこと。
