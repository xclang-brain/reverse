## 判定

番号ごとに、判定を1行で1つ書く。

| 判定 | 行の形 | 当てる行 |
| --- | --- | --- |
| OK | `[n] OK <根拠>` | 行の全部を、ソースコードで確かめた。 |
| NG | `[n] NG <根拠> <直した文>` | ソースコードと違う。直した文は、行の全体を置き換える文である。番号の行がコードブロックのときは、直した文を書かない。 |
| 不明 | `[n] 不明 <探した語>` | ソースコードで確かめられない。 |
| 対象外 | `[n] 対象外` | 事実を述べていない行。 |

- `<根拠>` は、`[<ソースコードのフォルダからの相対パス>:<開始行>-<終了行>]` を、空白1つで区切って1〜3個書く。1つの範囲は 150 行までにする。
- 行のバッククォートの中の語（NG では、直した文の語）は、全部が根拠のファイルにあり、1つ以上が根拠の行の範囲にあるようにする。ファイル名のように、ソースファイルのパスにある語は、根拠のファイルにあるものとして扱う。
- バッククォートの名前を含む行と、コードブロックの行は、OK、NG、不明のどれかにする。Mermaid のブロックの NG は、不明と同じに扱われる。
- Mermaid の図は、図の中の名前と、矢印が表す関係（呼び出し、依存、状態の移り）を、ソースコードで1つずつ確かめる。モジュールの名前と部分の名前は、モジュールの一覧で確かめる。全部を確かめられたら OK にし、根拠には、関係を確かめたソースファイルの場所を1〜3個書く。
- 直した文は、元の行と同じ形にする。表の行は同じ列の数で `|` で始めて `|` で終え、箇条書きは同じ字下げと記号で始め、要求の行は同じ `- <ID>: ` で始める。
- 直した文のうち、日本語でない文は、日本語に直して書く。名前と数値は、元の表記のまま書く。
- 直した文では、名前を省略せずに書く。名前の一部（接頭辞）を指すときは、`VALVE_*` の形で書く。

## 判定の例

例の名前は、形式を示すために作ったものである。

- 「`valve_close` は、閉じる操作を3回までやり直す。」は、コードで確かめられれば OK。
- 「通信が不安定なため、`VLV_RETRY_MAX` を `3` にしている。」は、理由がコメントにもコードにも書かれていなければ不明。
- `#if` の中の処理を、条件なしで述べた行は NG にし、条件を書いた文に直す。
- 行の一部だけを確かめられたときは NG にし、確かめられた部分だけの文に直す。「`valve_open` は、`valve_drain` を呼び、`VLV_OK` を返す。」で、`VLV_OK` を返すことだけを確かめられたときは、「`valve_open` は、`VLV_OK` を返す。」に直す。

```markdown
[1] OK [pump/valve.c:95-130]
[2] NG [pump/valve.c:52-90] - `USE_DRAIN` が定義されているとき、`valve_open` は `valve_drain` を呼ぶ。
[3] 不明 VLV_RETRY_MAX、通信、理由
[4] 対象外
[5] OK [pump/valve.c:10-40] [pump/valve.h:1-30]
```

## 根拠の決まり

- ソースコードについての記述の根拠は、対象のソースファイルだけである。

## してはいけないこと

- 文書のファイル（md、txt、html など）と、ほかの設計書を根拠にすること。
- 設計書を直接書き換えること。書くのは、判定の記録だけである。
- 直した文に、推測の言い回し（`と思われる`、`と考えられる`、`おそらく`、`かもしれない`、`はずである`、`と推測`）、`ファイル名:行番号` の形、`【既存設計書のみ】` の印を書くこと。
- 書く先のほかに、ファイルを書くこと。ソースコードを書き換えること。
