# 設計書を作る

ソースコードと既存の設計書（PDF）を読み取り、新しい設計書を作る。あなたは統括として、スクリプトが返す仕事を担当エージェントに渡し、最後まで進める。

人への返事は、日本語で書く。

## 準備

- Python は、Windows では `py -3`、それ以外では `python3` で呼ぶ。以下では `<python>` と書く。
- スクリプトは、このスキルのフォルダの `scripts/revdoc.py` である。以下では、`<python> "<このスキルのフォルダ>/scripts/revdoc.py"` を `<revdoc>` と書く。
- スクリプトは、結果を JSON で返す。`"ok": false` のときは、`error` と `message` を読む。

## 手順

### 1. 入力を読み取る

利用者の依頼から、次の3つを読み取る。

| 入力 | 決まり |
| --- | --- |
| ソースコードのフォルダ | 指示がなければ、使わない。 |
| PDF のフォルダまたはファイル | 指示がなければ、使わない。 |
| 出力先のフォルダ | 指示がなければ、作業フォルダの `design-docs` とする。 |

ソースコードと PDF のどちらも指示がないときだけ、場所を利用者に尋ねる。

### 2. 計画を作る

次のコマンドを実行する。指示がなかった入力のオプションは、付けない。

```
<revdoc> init --out "<出力先>" --src "<ソースコードのフォルダ>" --pdf "<PDF のフォルダまたはファイル>"
```

| 結果 | 行うこと |
| --- | --- |
| `"ok": true` | ユニット、モジュール、PDF のページの数を利用者に伝え、手順3へ進む。例：「準備ができました。ソースコードは 12 ユニット・4 モジュール、PDF は 40 ページです。ここからは最後まで自動で進めます。」 |
| `error` が `missing_packages` | `install` のコマンドを利用者に示し、実行してよいかを尋ねる。同意を得たら実行し、`init` をやり直す。 |
| そのほかの `error` | `message` を利用者に伝え、正しい場所を尋ねる。答えをもらったら、`init` をやり直す。 |

### 3. 仕事を進める

`done` が `true` になるまで、次を繰り返す。

1. `<revdoc> next --out "<出力先>"` を実行する。
2. `done` が `true` なら、手順4へ進む。
3. `tasks` の仕事ごとに、担当エージェントを1つ呼ぶ。同じ回の仕事は、1つのメッセージの中で、すべて並列で呼ぶ。
   - 担当エージェントの名前は、仕事の `agent` の値を使う（Claude Code では Agent ツールの `subagent_type`、GitHub Copilot CLI では task ツールの `agent_type`）。
   - 渡す指示は、次の1文とする：「次の指示のファイルを読み、そのとおりに作業してください：`<仕事の file の値>`」
4. 呼んだ担当エージェントがすべて返ったら、1 に戻る。出来の検査は、次の `next` が行う。
5. `stage` が前の回から変わったときは、進み具合を1文で利用者に伝える。例：「ソースコードの解析と PDF の変換が終わりました。既存の設計書とソースコードの照合に進みます。」

`stage` の意味は、次のとおり。

| `stage` | 行っていること |
| --- | --- |
| `analyze_convert` | ソースコードの解析と、PDF の変換 |
| `match` | 既存の設計書とソースコードの照合 |
| `write_modules` | モジュールの設計書の執筆 |
| `verify_modules` | モジュールの設計書の検証 |
| `write_overall` | 全体の内部設計書と要求仕様書の執筆 |
| `fix` | 検査で見つかった問題の修正 |

### 4. 表示する

`<revdoc> serve --out "<出力先>"` を実行する。`"ok": false` のときは、`message` を利用者に伝える。Markdown の設計書は出力先にできていることも伝える。

### 5. 結果を伝える

最後の `next` の `summary` と、`serve` の結果を使い、次の形で伝える。

```
設計書ができました。

- 出力先：<out>
- ブラウザーで見る：<url>
- モジュール：<modules> 件
- 食い違い：<discrepancies> 件（docs/review/discrepancies.md）
- 不明点：<unknowns> 件（docs/review/unknowns.md）

食い違いと不明点の一覧を確認してください。
表示用のサーバーを止めるときは、`<revdoc> stop --out "<out>"` を実行します。
```

- `tasks_failed` が 1 以上のときは、「失敗した仕事：<数> 件（不明点の一覧に載せました）」の行を足す。
- `check_passed` が `false` のときは、「構造の検査で直せなかった項目があります」の行を足し、`<revdoc> check --out "<out>"` の `problems` を伝える。

## 中断したとき

同じ出力先でこのスキルをもう一度呼ぶと、`init` が `"resumed": true` を返す。そのまま手順3から続ける。

## 禁止事項

- 手順3に入った後に、利用者に質問や確認をすること。
- `done` が `true` になる前に、作業を終えること。
- 担当エージェントの仕事を、自分で代わりに行うこと。
- `next` が返していない仕事を作ること。
- ソースコードと PDF を書き換えること。
