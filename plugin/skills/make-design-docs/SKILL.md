# make-design-docs

あなたは統括である。スクリプトの `init` を呼び、その後は、結果の `do` のとおりにする。仕事は、スクリプトと担当エージェントが行う。

## 1. 場所を決める

利用者の頼みから、次の3つを決める。ソースコードと PDF は、片方だけでもよい。

- ソースコードのフォルダ（`--src`）
- PDF のフォルダか、PDF のファイル（`--pdf`）
- 出力先（`--out`）。頼みにないときは、カレントフォルダの `design-docs`。

パスは絶対パスにして、単引用符で囲む。下のコマンドの `[` と `]` は書かない。ないものは、`[` から `]` までを省く。

## 2. init を呼ぶ

`<python>` は、Windows では `py -3`、それ以外では `python3` である。見つからないときは `python` にする。どれも見つからないときは、Python 3.9 以上が要ることを利用者に伝えて止まる。`<スキルのフォルダ>` は、この SKILL.md があるフォルダの絶対パスである。

```
<python> '<スキルのフォルダ>/scripts/revdoc.py' init --out '<出力先>' [--src '<ソースコードのフォルダ>'] [--pdf '<PDF のフォルダかファイル>']
```

止まった作業の続きも、同じコマンドで始める。

## 3. do のとおりに進める

- 結果は JSON の1行である。`do` に、次にすることと、次に呼ぶコマンドの全文が書いてある。コマンドは、書かれたとおりに1行で実行する。
- コマンドが終わるまで待つ。同じコマンドを重ねて動かさない。
- `jobs` があるときは、仕事ごとに担当エージェントを1体ずつ、1つの返事の中でまとめて呼ぶ。担当の名前は仕事の `agent`、頼みの文は `do` に書かれた1文である。全部の担当の結果が返ってから、次のコマンドを呼ぶ。
- `state` が done になったら、`do` のとおりに `serve` を呼び、その結果の `do` のとおりに、利用者に日本語で伝える。
- `ok` が false のときは、`do` のとおりに利用者に伝えて止まる。

担当エージェントの呼び方は、次のとおりである。

| ツール | 呼ぶツール | 担当の名前 | 結果を待つ指定 |
| --- | --- | --- | --- |
| Claude Code | Agent | `subagent_type` | `run_in_background: false` |
| GitHub Copilot CLI | task | `agent_type` | `mode: "sync"` |

## してはいけないこと

- 利用者に質問すること。
- 指示のファイルと、担当エージェントが書いたファイルを読み書きすること。担当の仕事を自分で行うこと。
- `state` が done になる前に、まとめを書くこと。
- コマンドに、`&&`、パイプ、リダイレクト、環境変数の前置き、行の継続を使うこと。
