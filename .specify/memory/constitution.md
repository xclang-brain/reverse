# reverse Constitution

## Core Principles

### I. IPA「AI時代の要求管理ハンドブック」の採用

本リポジトリの開発は、IPA「AI時代の要求管理ハンドブック」に準拠する。
内容は原典を参照すること。

- 原典（PDF）: https://www.ipa.go.jp/digital/kaihatsu/rqr7mi000000f5up-att/req-mgmt-hb.pdf

### II. Anthropic 公式のテスト手法の採用

本リポジトリのテストは、Anthropic が公式に示す手法（テスト駆動開発、および
テスト作成・実装・検証を独立したエージェントに分離するやり方）に準拠する。
内容は原典を参照すること。

- https://www.anthropic.com/research/claude-code-best-practices
- https://code.claude.com/docs/en/best-practices
- https://claude.com/resources/articles/the-ai-native-sdlc-playbook

### III. 分かりやすい日本語（絶対ルール）

本リポジトリの文書・コメント・コミットメッセージ・報告は、すべて分かりやすい日本語で書く。
この原則は例外なく適用する。

#### 書き方

1. **一般的な用語を使う**：広く通じる言葉を選ぶ。
2. **自然な日本語で書く**：日本語として普通に読める言い回しにする。
3. **抽象から具体へ進める**：結論や全体像を先に示し、詳細へ掘り下げる（ピラミッド構造）。
4. **見出しで構成を示す**：内容に合った見出しを付け、読みたい箇所をすぐ探せるようにする。
5. **優先順位を付ける**：優先度の高いものを先に、低いものを後に書く。
6. **本文は正常系を書く**：本筋は「何をするか」で書き、禁止事項や例外は一箇所にまとめる。

#### 禁止事項

- 独自の用語を使うこと
- 英語を直訳したような不自然な日本語を使うこと
- 否定文や例外条件を本文中に散りばめること

### IV. シンプルな実装（KISS）

少ない分量で質の高いものを作ることを最善とする。量と品質は比例しない。
この原則はコードと文章の両方に適用する。

#### 進め方

1. **最小の分量で目的を満たす**：要求を満たす最も単純な形を選ぶ。
2. **既存のものを直す**：追加の前に、既存のコードや文章の修正・統合で済むかを確かめる。
3. **不要になったものを消す**：使われなくなったコードや文章は、その都度削除する。

#### 禁止事項

- 継ぎ足しを重ねてリポジトリを肥大化させること
- 分量の多さを成果や品質の根拠にすること
